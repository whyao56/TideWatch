# 2026-10-03 · 爆发信号背景速率的修正

关联：`docs/design-decisions.md` 的 **D12** 与 **B8**。

## 问题

`BurstSignal` 原本用**话题自身**的平均到达密度当基准：

```python
baseline = len(timed) / span          # span 是这一个话题的时间跨度
local_density = best_count / window   # window 是名义窗口长度（300 秒）
ratio = local_density / baseline
```

两处都有毛病：

1. **自我抵消**：一个整体就是集中投放的话题，它的平均密度早就被投放本身
   拉高了，于是比值恒等于 1，**永远检不出自己**。
2. **量纲不一致**：`baseline` 用的是话题的**真实跨度**，
   而 `local_density` 用的是**名义窗口长度**。当话题的整个跨度小于窗口时
   （例如 8 条发言总共只铺了 14 秒），`local_density` 会被分母 300 严重稀释。

## 症状（第 2 点的具体表现）

手写测试想验证「协同层必须跨账号」，用了 8 条来自 8 个账号、间隔 2 秒的发言：

```
8 条 / 14 秒跨度，全部落在 300 秒窗口内
baseline       = 8 / 14  = 0.571 条/秒
local_density  = 8 / 300 = 0.027 条/秒
ratio          = 0.047            ← 远低于阈值 2.5
```

结果是信号不触发，测试失败。而**这个数据看起来明明就是一次爆发** ——
8 个账号在 14 秒内齐刷刷开口。

## 修正

两处一起改：

```python
# 1. 背景速率取自**整个数据集**（所有话题），而不是话题自身
background = len(timed_all) / max(bg_span, 1.0)

# 2. 用这一段自己的**真实跨度**算速率，而不是名义窗口长度
span_sec = max((t1 - t0).total_seconds(), 1.0)
local_rate = best_count / span_sec
ratio = local_rate / background
```

修正后同一份数据的比值：

```
8 条 / 14 秒跨度，数据集内另有 40 条正常发言铺在 7020 秒里
background = 48 / 7020 = 0.00684 条/秒
local_rate = 8 / 14    = 0.571   条/秒
ratio      = 83.5                 ← 远超阈值
```

## 影响面

跑了一遍全部 7 组消融，**指标无变化**：

```
全量     item P/R/F1 1.000/0.096/0.175  actor P/R/F1 1.000/1.000/1.000  团伙3
仅协同层  item P/R/F1 0.000/0.000/0.000  actor P/R/F1 1.000/0.725/0.841  团伙3
```

原因是合成数据里本来就有大量平缓的正常活动（120 条 normal 铺在很长时间上），
两种背景速率的算法在这一份数据上没有分歧。

**所以这次改动在指标上不可见。** 它是**原理修正**，不是性能优化。

## 为什么要做这次改动

因为它改变了信号在**退化数据**上的行为。原来的实现会在两种情况下给出
错误答案，而这两种情况在新实现下会正确地**弃权**：

| 数据情况 | 原实现 | 新实现 |
|---|---|---|
| 整批数据只有一段紧挨着的爆发（无背景） | 比值 ≈ 1，安静地不报 | 比值 ≈ 1，**弃权**（行为相同但原因不同：不再是"稀释"而是"没有参照物"） |
| 话题跨度远小于窗口 | 被名义窗口稀释，漏报 | 用真实跨度，正确评估 |

第一条是新旧行为**相同但解释不同**：旧实现是「凑巧不报」，新实现是
「明确地弃权」。

```python
    )

```

以及夹具的真实化修正（`tests/conftest.py` 的 `dataset` fixture）：
补进了 12 条铺在 2.75 小时里的正常发言。**没有这段背景，
`test_time_burst_is_found` 验证的会是「弃权」而不是「检出」——
一条看起来通过、实际什么都没测到的假测试。**

## 观察（数字）

修正后 `data/sample/sample.jsonl` 上的爆发命中：

```
target  burst:video-1002:2026-09-01T14:00:00+00:00   level=弱嫌疑
reason  「video-1002」在 154 秒内集中出现 15 条
        （来自 15 个账号，平均每秒 0.10 条，是背景速率的 5.9 倍）
```

15 条、15 个账号、5.9 倍背景速率 —— 注入的是 15 条 burst，全部检出，无附加误报。

## 结论

1. 这次改动**不改变**任何已经写进 README 的数字。不要把它当成性能提升。
2. 它的价值是让信号的**前提假设**变得显式：爆发是相对量，
   没有背景就不该下结论。这个「能弃权」的行为现在有测试守着。
3. 顺带暴露了一个方法论问题：**指标不变不等于改动没价值。**
   如果只按指标做决策，这次正确的原理修正会被判定为「无用」而回滚。
