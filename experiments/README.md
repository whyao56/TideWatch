# 实验记录

这个目录放**原始实验日志**，一份实验一个文件，命名 `YYYY-MM-DD-<主题>.md`。

## 为什么要单独记一份

`docs/benchmark.md` 是自动生成的，它只保留**最新一次**的结果。
而这个项目里真正重要的东西是**变化**：

- 改了哪个参数，指标从多少变成多少
- 哪次改动在合成数据上看不出差别，但修正了一个原理错误
- 哪个结论当时的解释是错的，后来怎么纠正的

这些在自动报告里留不下痕迹，但它们才是「做过研究」的证据。

## 一份记录里必须有的四样东西

1. **配置指纹** —— 12 位 sha256，由 `Config.fingerprint()` 生成。
   没有它，三个月后你看这张表格根本不知道是拿哪套参数跑出来的。
2. **数据 fingerprint** —— 数据行数、账号数、生成方式（或来源）。
3. **原始输出** —— 直接粘贴 CLI 或评测脚本的输出，不做二次加工。
4. **观察与结论** —— 但要区分开「观察到的数字」和「我的解释」。
   解释可能是错的，数字不会。

## 命名与格式

文件名用日期开头，方便按时间排序。`docs/design-decisions.md` 第二部分
（踩坑记录）里的 B 编号会被这些记录引用 —— 两边是交叉的。

> 注意：不要把「解释」写成「结论」。这份文档的读者是三个月后的你自己，
> 那时你已经忘了当时的语境，只会照着字面理解。写清楚哪些是数字、
> 哪些是推断，比写得漂亮重要得多。
