# TideWatch · 观潮 v0.0.1

**第一个 Windows 免安装发行版。** 解压即用，不需要装 Python、不需要装任何依赖。

TideWatch 是一个可解释、可插拔、可迭代的**网络水军与协同行为识别引擎**。
它不靠单账号特征（那早就没用了 —— 买个养了半年的号成本极低），
而是看账号之间的**协同性**：对手可以伪造身份，但很难伪造「各自独立」。

|---|---|
| `TideWatch-0.0.1-win64.zip` | Windows x64 免安装包，解压即用 |
| `TideWatch-0.0.1-win64.zip.sha256` | 校验和 |

解压后是这样一个文件夹：

```
TideWatch-0.0.1-win64/
├── TideWatch.exe
├── configs/                 ← 可以直接改
├── rules/                   ← 可以直接改（微调的主要入口）
├── data/sample/             随包的 193 条样例数据
├── _internal/               运行库，不要动
├── README.md                完整文档
├── 使用说明.md              快速上手
└── LICENSE                  MIT
```

在解压出来的目录里开一个 PowerShell：

```powershell
.\TideWatch.exe doctor
.\TideWatch.exe scan data\sample\sample.jsonl --evidence
```

## 这一版做了什么

**打包这条链路上真正难的不是「打出 exe」，是「打出来之后还对不对」。**
下面每一条都是实测过的，不是设计意图。

- **免安装、自带运行时**。onedir 形态。选它而不是 onefile 的原因很具体：
  这个项目的核心用法是**改 `rules/*.yaml` 微调**，而 onefile 每次启动都把自己
  解压到随机临时目录、退出即删 —— 使用者改完的规则下一次就没了。
- **一条命令构建**：`python scripts/build_exe.py`。构建脚本自带对产物的冒烟检查
  （跑 `--version` / `doctor` / `scan` 并断言结果），CI 和本地走同一条脚本。
- **新增 `tidewatch doctor` 自检**：打印版本、程序目录、资源根、配置指纹、规则库
  统计，并且**真的跑一遍最小数据集**确认引擎能出结论 —— 它回答的是「能不能用」，
  不是「库导进来了没有」。三档结论 `ok` / `warn` / `fail`，`fail` 时给出可操作的下一步。
- **修正了打包后必然踩到的两处**：
  - *控制台编码*：Windows 简体中文环境下冻结程序的 `stdout` 是 GBK，
    而样例数据里有 `❤️`。实测表现为
    `UnicodeEncodeError: 'gbk' codec can't encode character '\u2764'` —— 直接崩。
    现在会切控制台代码页并重绑流编码。
  - *资源路径*：`configs/` 与 `rules/` 的定位从「靠 `__file__` 反推」改成
    单一的路径解析模块。旧写法在 onedir + 同级资源齐全时**碰巧是对的**
    （`_internal` 恰好比 exe 低一层），但只要回落到兜底副本，判断它的地方和
    使用它的地方就会各找到一个不同的目录 —— 实测 `doctor` 会同时打印
    「配置文件在 `_internal/configs/...`」和「配置加载：找不到配置文件」。
- **双击不再一闪就关**：无参数 + 从资源管理器启动时打印用法并等一次回车。
  这是打包后最糟的失败方式 —— 连「哪里错了」都看不到。
- **版本号只有一处**（`src/tidewatch/version.py`），exe 属性里也是它，
  有测试盯着 `pyproject.toml` 和 `configs/default.yaml` 不许跑偏。
- **测试从 161 条增加到 183 条**。新增的每一条都先在旧代码上跑过、确认会失败，
  才留下来。

## 校验和

```powershell
Get-FileHash .\TideWatch-0.0.1-win64.zip -Algorithm SHA256
```

和同目录下 `.sha256` 文件里的值比对。

**这个校验和用来核对下载，不能用来核对构建。** 打包那一步是确定的
（zip 里文件名排序固定、时间戳写死，同一份目录连打两次 SHA 必然相同）；
但 PyInstaller 构建本身不是逐字节确定的，你自己重跑一遍构建得到不同的 SHA 是正常的。

## 需要知道的三件事

**1. Windows 可能会拦。** 本包**没有代码签名**（证书一年几百美元，本项目没买），
所以首次运行 SmartScreen 会提示「已保护你的电脑」。点「更多信息」→「仍要运行」。
请用上面的校验和自行核对。

**2. 样例数据上的高分不能当性能背书。** 那 193 条数据是自己注入的，
注入模式天然贴合引擎里的信号，在这种数据上刷高分没有信息量。
README 和 `docs/benchmark.md` 里主动写了这条边界。
**有意义的是消融实验的结论**：三层互补 —— 账号层单独能判准账号但一个团伙都发现不了，
协同层单独能挖出全部团伙但账号召回只有 0.725。

**3. 这是分析引擎，不是判决器。** 输出是**嫌疑分级和证据**，正确用法是
「把 10000 条评论缩到 200 条值得人看的」，不是自动封号。
使用前请自行确认数据来源合法、不传播可识别到自然人的信息、
结论仅用于人工复核。
